## Topic(s)

- 研究テーマを固定せず、異なる視点を混ぜて新しいRQを発生させる仕組み

## Related Research

- RQ: 新しい研究問いをゼミ会話からどのように発生させるか
- EXT: Seminarを研究構造のフィードバック層として扱う
- EXP: Phase 1で検討

## Discussion

### 黒田 — 問いを壊す

5人を専門分野ごとに固定するのではなく、同じテーマに異なる人格で参加させる。Personaは「誰が喋るか」を定義する。

### 佐伯 — 構造化する

`persona/` と `seminar/` を分離する。

- `persona/` = 人格・役割・会話レンズ
- `seminar/` = 実際の議論・議事録
- `questions/` = 発生した研究問い

口頭の議論を記録し、そこから次の研究構造へ接続する。

### 神谷 — 反証する

Personaを単なるキャラクター設定にせず、研究上の異なる認識作用として定義する必要がある。

特に「雑談から生まれたアイデア」と「研究問いとして成立したもの」を区別する。

### 三浦 — 作ってみる

5人のPersonaをREADMEとして実装し、Seminar templateと組み合わせて運用できる状態にする。

### 中野 — そもそも？

「なんで5人に分けるのか？」という疑問自体を研究対象にできる。

人格を分けることで、本来一人の研究者の頭の中にある異なる視点を外在化できるのではないか。

## Unexpected Connections

- Persona = 認識の分離装置
- Seminar = 認識を再結合する場
- GitHub = 会話を研究構造へ変換する記録媒体
- AI Agent = Personaごとの視点を持つ研究参加者になり得る

## Decisions

1. `persona/README.md` に5人のラボメンバー定義を保存する。
2. `seminar/` に議事録を保存する。
3. Personaは専門テーマではなく、研究議論における役割・視点として扱う。
4. Seminarは成果アーカイブではなく、研究構造を更新するフィードバック層とする。

## New RQ Candidates

- RQ-CAND-001: 複数のPersonaによる議論は、単一研究者の思考と異なる研究問いを生成できるか。
- RQ-CAND-002: Personaを認識作用として分離することで、研究上の反証・飛躍・未検討前提を発見しやすくなるか。
- RQ-CAND-003: GitHub上のPersona → Seminar → RQ構造を研究支援システムとして運用できるか。
