## 観察
学会には少なくとも次の構造がある。

```text
Conference
  ├─ Domain
  ├─ Genre
  ├─ Session
  ├─ Topic
  ├─ Submission Type
  ├─ Paper / Abstract
  └─ Presentation
       └─ Question / Discussion
```

研究発表は、研究結果の一方向的な配布ではなく、質問と応答を含むResearch Experienceとして扱える。

## 建築研究との接続
日本建築学会大会では、材料施工、構造、環境工学、建築計画、都市計画、歴史・意匠、情報システム技術、建築デザインなど複数の部門に研究が分類されている。citeturn0search0

また、建築学会の研究発表は本人発表と質疑討論から構成される。citeturn0search17

したがって、学会Corpusでは「何について研究されているか」だけでなく、「どのような形式で研究が提示され、どのような議論を要求しているか」を構造化する。

## 今日の仮説
> 学会プログラムをDomain / Genre / Topic / Session / Submission Type / Presentationとして構造化すると、その分野が現在何を研究対象としているかを比較可能なCorpusとして記述できる。

## 反証
- プログラム分類は学会運営上の都合であり、研究領域そのものを表していない可能性がある。
- 発表タイトルだけでは研究方法やEvidenceを判定できない。
- 学会ごとに分類体系が異なるため、単純比較では意味が失われる可能性がある。
